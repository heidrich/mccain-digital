(03) — How deep we go

Boring stack, fast app.

Four decisions decide whether an app scales or gets rewritten. We make them at the start, where they're cheap.

A modern, typed stack

React and Next.js with TypeScript end to end — server components for fast first loads, the App Router, a typed data layer with Prisma or Drizzle on PostgreSQL. Boring on purpose: a huge talent pool, long support, nothing exotic you'd struggle to hire for in two years.

Typed end to end

Core Web Vitals, green from day one

Performance is an architecture decision, not a cleanup at the end. Small bundles through server components and streaming, indexed queries and caching instead of N+1 loops, and a Lighthouse budget in CI so a regression fails the build. This site scores 100 — that's the proof.

Budgeted in CI

Architecture that scales

A clean data layer, typed APIs (tRPC or REST), real auth and roles — designed so the MVP and the scaled app are the same codebase. Schema, indexes, caching and queue work happen up front, so growth means adding load, not starting over.

One codebase, MVP to scale

Real-time & integrations

Live updates over websockets, Stripe for payments and subscriptions, auth providers (OAuth, magic links, SSO) and the third-party APIs your product leans on — webhooks, retries and idempotency handled, so integrations are reliable instead of the thing that pages you at 2am.

Webhooks · retries · idempotency
